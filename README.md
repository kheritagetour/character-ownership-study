## 1. 실험 설계 요약

| 항목 | 내용 |
|---|---|
| 설계 | 참가자 간 설계(between-subjects), 2조건 |
| IV | AI 이미지 생성에서의 사용자 관여 형태 — **A** 단일 생성 / **B** 반복 프롬프트(결과 확인 후 수정) |
| 유일한 차이 | 2단계에서 **AI 결과를 보고** 프롬프트를 고치는지 여부 (작성 횟수·시간·길이 범위는 동일) |
| N | 12명 (조건당 6명), 4명 단위 블록 무선배정 |
| 1차 DV | 심리적 소유감 PO (Chung et al., 2024 · 5문항 · 7점) |
| 탐색 | 의도 일치도 IA (자체 개발 · 3문항 · 컨셉 시트/스케치 옆에서 평정) |
| 2차 DV | 지각된 저자성 AU (2문항) + 공개 시 저자 표기 (Draxler et al., 2024) |
| 조작 점검 | 지각된 창작 통제감 CC (Gong & Chen, 2026 · 3문항) |
| 공변량 | 지각된 품질, 지각된 노력 (0–100, Pennanen et al., 2026) |
| 가설 | **H1** B > A (PO). RQ2: IA와 PO의 관계 (조건 포함 회귀) |

### 조건별 조작 (교수님 피드백 반영 — 시간·길이 교란 통제)

| | A · Single Generation | B · Iterative Prompting |
|---|---|---|
| 1단계 (정확히 3분) | 프롬프트 작성 | 프롬프트 작성 → 1차 이미지 생성 |
| 2단계 (정확히 3분) | 이미지 **없이** 프롬프트 검토·다듬기 | 1차 이미지를 **보고** 프롬프트 수정 |
| 최종 | 2단계 프롬프트로 1회 생성 | 2단계 프롬프트로 생성 (마지막 결과 고정) |
| 생성 횟수 | 1 | 2 |

**왜 이렇게 바꿨나 (피드백 요지)**: 원래 설계(A 1회 / B 최대 3회, 6분 내 자유)는 A가 한 줄만 쓰고 일찍 끝내거나 반대로 한 번에 모든 정보를 몰아넣을 수 있어서, 결과 차이가 '횟수' 때문인지 '작성 시간·프롬프트 길이' 때문인지 구분할 수 없었음.

**통제 방법**
- **시간**: 두 조건 모두 작성 2단계 × 정확히 3분. 일찍 넘어갈 수 없고, 시간이 끝나면 자동으로 넘어감.
- **길이**: 모든 프롬프트 60–400자 (A/B 동일). 최소 글자 수 미달이면 채울 때까지 대기(초과 시간 기록).
- **작성 횟수**: 두 조건 모두 프롬프트를 두 번 씀 (A의 2단계 = 결과 없이 다듬기).
- **사후 점검**: 단계별 글자 수·입력량·편집거리를 기록해 조건 간 균형 확인(분석 6b), 최종 프롬프트 길이를 공변량으로 투입.
- **남는 차이**: B는 1차 결과를 보고 2단계를 진행하며, 이미지 생성을 기다리는 시간(수십 초)이 한 번 더 있음.

### 두 조건 간 동일하게 통제되는 것
- 같은 세계관 텍스트(「등불의 군도」), 같은 과제 지시문
- 같은 생성 모델, 같은 숨은 스타일 접미사(`STYLE_SUFFIX`), 같은 출력 크기(768×1024, 3:4)
- AI 사용 **전에** 컨셉 시트 + 손 스케치 작성 (의도를 사전에 고정)
- 같은 사후 설문, 같은 순서

## 4. 분석

```bash
python3 analysis/analyze.py ~/Downloads/ownership_study_2026-11-20-15-00.csv --out results.md
python3 analysis/analyze.py data.csv --include-test     # 파일럿 데이터까지 포함해 점검
```

| 보고서 섹션 | 분석 | PDF 대응 |
|---|---|---|
| 1 | Cronbach's α (PO, IA, CC), AU 2문항 r / Spearman-Brown | "reliability re-checked on our data" |
| 2 | CC: Welch t (단측 B>A), Hedges' g + 95% CI, exact permutation, Mann-Whitney | Manipulation check |
| 3 | **PO: 동일 (H1)** | Main |
| 4a | AU: Welch t (양측) | Secondary |
| 4b | 저자 표기: Fisher exact (Myself vs. 그 외) + 전체 표 permutation χ² | Secondary |
| 5 | r(IA, PO) 전체/조건별, OLS `PO ~ IA + Cond`, 탐색적 `IA × Cond` | RQ2 |
| 6 | OLS `PO ~ Cond + Quality + Effort` | Covariates |
| 6b | 단계별 길이·입력량·편집거리 조건 비교, OLS `PO ~ Cond + 최종 프롬프트 길이` | 시간·길이 교란 점검 |
| 7–8 | 과정 로그 기술통계, 사전 특성 균형 점검 | Appendix A5 |

## 5. 설계상 주의할 점 (발표·보고서에 언급 권장)

1. **검정력**: 조건당 6명이면 80% 검정력(α=.05, 단측)에 **d ≈ 1.54**가 필요 (양측 ≈ 1.80). d = 0.8을 검출하려면 조건당 약 21명. → 제안서대로 효과크기와 CI 중심으로 보고하고, exact permutation test를 함께 제시 (12명이면 924개 배정 전부 열거 가능).
2. **B의 최종 이미지는 마지막 결과로 고정**: 여러 결과 중 '고르는' 관여가 섞이지 않게 함. 단, B 참가자는 2차 결과가 1차보다 나빠도 되돌릴 수 없음 → 안내 화면에 명시, 자유응답에서 불만이 나오는지 확인.
3. **시간·길이 통제의 한계**: 작성 시간과 길이 범위는 맞췄지만, 범위 안에서의 길이와 실제 입력량은 참가자마다 다름 → 분석 6b에서 조건 간 균형을 보고하고 최종 프롬프트 길이를 공변량으로 투입. 고정 시간 때문에 일찍 끝낸 참가자가 기다리는 상황이 생길 수 있음(파일럿에서 3분이 적절한지 확인).
4. **생성 지연/실패**: 실패한 생성은 자동으로 다시 시도하며 횟수에 포함하지 않고 로그에 남음. 본 실험은 생성 속도가 일정한 유료 API(OpenAI) 권장.
5. **번역 문항**: PO·CC·AU는 영어 원문을 번역/개작함 (앱에 영문 병기). 보고서에 번역 절차와 우리 데이터의 α를 기재.
