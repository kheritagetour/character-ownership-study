## 1. 실험 설계 요약

| 항목 | 내용 |
|---|---|
| 설계 | 참가자 간 설계(between-subjects), 2조건 |
| IV | AI 이미지 생성에서의 사용자 관여 형태 — **A** 단일 생성 / **B** 반복 프롬프트(1차 결과를 보고 선택적으로 수정 후 재생성) |
| 유일한 차이 | 1차 결과를 본 뒤 **프롬프트를 수정해 다시 생성할 기회**가 있는지 (1차 작성 시간·길이 범위·스케치 입력은 동일) |
| N | 12명 (조건당 6명), 4명 단위 블록 무선배정 |
| 세계관(자극) | 2개 — 「별빛 마법학교」 / 「2087 네온시티」. 조건 × 세계관 균형 배정 (각 칸 3명) |
| 1차 DV | 심리적 소유감 PO (Chung et al., 2024 · 5문항 · 7점) |
| 탐색 | 의도 일치도 IA (자체 개발 · 3문항 · 컨셉 시트/스케치 옆에서 평정) |
| 2차 DV | 지각된 저자성 AU (2문항) + 공개 시 저자 표기 (Draxler et al., 2024) |
| 조작 점검 | 지각된 창작 통제감 CC (Gong & Chen, 2026 · 3문항) |
| 공변량 | 지각된 품질, 지각된 노력 (0–100, Pennanen et al., 2026) |
| 가설 | **H1** B > A (PO). RQ2: IA와 PO의 관계 (조건 포함 회귀) |

### 조건별 조작 (교수님 피드백 반영 — 시간·길이 교란 통제)

| | A · Single Generation | B · Iterative Prompting |
|---|---|---|
| 1차 프롬프트 (A/B 동일) | 작성 **정확히 3분**, 60–400자 → **손 스케치 + 프롬프트**로 생성 | 같음 |
| 1차 결과 이후 | 1차 이미지가 최종 | 결과를 보고 **선택**: ① 그대로 확정 ② 프롬프트 수정(최대 3분) → **스케치 + 수정 프롬프트**로 1회 재생성 |
| 최종 이미지 | 1차 | 수정했으면 2차, 아니면 1차 |
| 생성 횟수 | 1 | 1–2 |

**스케치 반영**: 손 스케치를 이미지 입력으로 함께 보내고(OpenAI `images/edits`), 프롬프트 앞에 "스케치를 자세·실루엣·비율의 주 참고로 삼으라"는 고정 지시문(`SKETCH_INSTRUCTION`)을 붙임. 두 조건, 모든 생성에 동일.

**왜 이렇게 바꿨나 (피드백 요지)**: 처음 설계(A 1회 / B 최대 3회, 6분 내 자유)는 A가 한 줄만 쓰고 일찍 끝내거나 반대로 한 번에 모든 정보를 몰아넣을 수 있어서, 결과 차이가 '횟수' 때문인지 '작성 시간·프롬프트 길이' 때문인지 구분할 수 없었음.

**통제 방법**
- **1차 작성 완전 동일**: 두 조건 모두 정확히 3분(일찍 끝낼 수 없음), 60–400자. 첫 프롬프트에 들이는 시간과 정보량을 맞춤.
- **사후 점검**: 1차 글자 수·입력량을 조건 간 비교(분석 6b), 최종 프롬프트 길이를 공변량으로 투입.
- **남는 차이 (= 조작)**: B는 1차 결과를 보고 고칠 기회가 있음. 수정은 선택이라 B 안에서 수정한 사람/안 한 사람이 나뉨 → 수정 여부(`b_revised`)와 수정량을 기록해 기술적으로 보고 (자기선택이라 B 내부 비교는 인과 해석 불가). 주 분석은 배정된 조건 기준(A vs B).

### 두 조건 간 동일하게 통제되는 것
- 같은 과제 지시문, 같은 세계관 세트 (각 조건 안에서 두 세계관이 3명씩)

### 세계관을 2개로 무작위 배정한 이유
처음 세계관(「등불의 군도」)이 낯설어 이해하기 어렵다는 의견이 있어, 익숙한 장르 두 개로 바꾸고 각각 "이런 인물들이 살고 있어요" 예시를 붙였음. 세계관을 주는 방식은 세 가지를 검토함.

| 방법 | 판단 |
|---|---|
| 참가자가 2개 중 **선택** | ✗ 선택 행위 자체가 자율성·소유감을 높여 종속변수(PO)를 직접 건드림. 자기선택 편향 |
| 한 명당 **2개 모두 진행** | ✗ 소요 시간이 약 2배(45분 이상), 피로와 1회차 학습 효과가 2회차에 섞임 |
| **2개 중 하나를 무작위·균형 배정** | ✓ 결과가 특정 세계관 하나에 국한되지 않음을 보일 수 있음(자극 일반화). 조건마다 세계관 구성이 같아 교란 없음. 분석에서 세계관을 공변량으로 통제(6c) |
- 같은 생성 모델, 같은 숨은 스타일 접미사(`STYLE_SUFFIX`), 같은 출력 크기(768×1024, 3:4)
- AI 사용 **전에** 컨셉 시트 + 손 스케치 작성 (의도를 사전에 고정)
- 같은 사후 설문, 같은 순서

## 2. 절차 (참가자 1인, 약 25분)

| # | 단계 | 내용 | 예상 시간 |
|---|---|---|---|
| 0 | 연구자 준비 | 앱에서 참가자 ID 선택 → 조건 자동 배정 → 세션 시작 | — |
| 1 | 동의 | 연구 안내 + 동의 체크 | 1분 |
| 2 | 사전 설문 | 텍스트/이미지 AI 사용 빈도, 사용 도구, AI 자기효능감, 그림 경험(3단계: 거의 없음/취미/전공·업무), 캐릭터·스토리 창작 경험(3단계), 그림 실력, 나이/성별 | 2분 |

| 5 | 손 스케치 | 앱 내 캔버스(펜/태블릿) 또는 종이에 그려 사진 업로드 | 3분 |
| 6 | AI 생성 안내 | 조건별 규칙 안내 | 0.5분 |

| 8 | 사후 설문 1 | PO 5문항 (최종 이미지 보며) | 1분 |

| 10 | 사후 설문 3 | AU 2문항, 공개 시 저자 표기, CC 3문항 | 1.5분 |
| 11 | 사후 설문 4 | 품질·노력 슬라이더, 자유응답 2개(선택) | 1.5분 |

> **목표: 30분 이내.** 예상 A 약 22분, B 약 22–26분(수정 여부에 따라). 고정 시간은 1차 프롬프트 3분뿐이라, 넘칠 위험은 컨셉 시트(권장 5분)와 스케치(권장 3분) → 두 화면에 경과/권장 시간을 표시하고 넘기면 마무리 안내(강제 종료는 안 함). 분석 보고서 7절에 총 소요 시간과 30분 초과 인원이 나옴. 모집 공고에는 "약 25분(최대 30분)"으로 표기.

**설문 순서 근거**: 1차 DV(PO)를 가장 먼저 측정해 다른 문항(특히 IA 비교 화면)이 소유감 응답을 오염시키지 않도록 함. IA는 PO 다음에 컨셉 자료를 보여주며 측정.

## 3. 앱 사용법

### 온라인 테스트 링크
**https://kheritagetour.github.io/character-ownership-study/** — 설치 없이 Chrome에서 바로 열림 (실제 AI 이미지 생성 포함).
- 팀원 테스트 시: `테스트/파일럿 세션`에 체크 → 모델은 Pollinations(실제 이미지) 또는 Mock(빠른 흐름 점검) 선택 → 세션 시작.
- 응답 데이터는 **각자 브라우저에만** 저장됨. 테스트 후 연구자 화면에서 `CSV 내보내기`로 받아 공유.
- `main` 브랜치에 push하면 1–2분 뒤 자동 반영.

### 실행
`index.html`을 Chrome에서 더블클릭하여 열기. 서버 불필요. 데이터는 **그 브라우저의 IndexedDB**에 저장되므로 **모든 세션을 같은 노트북·같은 브라우저 프로필**에서 진행할 것.

### 연구자 화면
- **참가자 ID**: 무선배정표 순서대로 다음 ID가 자동 선택됨. 조건도 자동으로 채워짐.
- **이미지 생성 모델** (기본값: OpenAI — 키가 없으면 세션 시작이 막힘)
  - `Pollinations (FLUX)` — 무료, 키 불필요. **IP당 45초에 1장** 제한(단계가 3분씩이라 실험 흐름에는 거의 영향 없음). 영어 프롬프트 권장 안내가 자동으로 붙음. → **테스트·파일럿용**
  - `OpenAI GPT Image` — 유료 API 키 필요(그 브라우저 localStorage에만 저장). 모델(gpt-image-1.5 / 1 / 1-mini)과 화질(low/medium/high) 선택. 한국어 프롬프트 이해 우수. → **본 실험 권장: gpt-image-1.5 · medium**. OpenAI 대시보드에서 사용 한도(예: $10)를 걸어 둘 것. 키는 연구자 노트북에만 입력하고 팀원에게 공유하지 말 것.
  - `Mock` — 가짜 이미지. 인터넷 없이 흐름 리허설용.
- **생성 연결 테스트**: 세션 시작 전 매일 1회 눌러서 모델이 응답하는지 확인.
- **테스트/파일럿 세션** 체크 → CSV에 `is_test=1`로 표시되어 분석에서 자동 제외.
- 진행 중 **Ctrl+Shift+A** → 일시정지하고 연구자 화면. 목록에서 "재개" 가능.
- **CSV 내보내기**: 분석용 1인 1행. **전체 JSON**: 이미지(최종·모든 시도·스케치)와 이벤트 로그 포함 원자료.
- 각 세션 종료 시 `P01_xxxx.json` 백업 파일이 다운로드 폴더에 자동 저장됨.

### 기록되는 과정 로그 (Appendix A5-E)
1차·2차 프롬프트 원문·글자 수·입력 이벤트 수·작성 시간·종료 방식(시간 종료/버튼/취소), B의 수정 여부와 결정 시간, 1→2차 편집거리, 스케치 사용 여부, 생성 요청·응답 시각과 지연시간, 시드, 실패 여부, 화면별 진입 시각, 스케치 획 수·소요 시간.

### CONFIG (index.html 상단)
| 키 | 기본값 | 설명 |
|---|---|---|

| `IMAGE` | 768×1024 | 출력 크기 |

## 4. 분석

```bash
python3 analysis/analyze.py ~/Downloads/ownership_study_2026-11-20-15-00.csv --out results.md
python3 analysis/analyze.py data.csv --include-test     # 파일럿 데이터까지 포함해 점검
```

| 보고서 섹션 | 분석 | PDF 대응 |
|---|---|---|
| 1 | Cronbach's α (PO, IA, CC), AU 2문항 r / Spearman-Brown | "reliability re-checked on our data" |
| 2 | CC: Welch t (단측 B>A), Hedges' g + 95% CI, exact permutation, Mann-Whitney | Manipulation check |
| 3 | **PO: 동일 (H1)** | Main |
| 4a | AU: Welch t (양측) | Secondary |
| 4b | 저자 표기: Fisher exact (Myself vs. 그 외) + 전체 표 permutation χ² | Secondary |
| 5 | r(IA, PO) 전체/조건별, OLS `PO ~ IA + Cond`, 탐색적 `IA × Cond` | RQ2 |
| 6 | OLS `PO ~ Cond + Quality + Effort` | Covariates |
| 6b | 1차 길이·입력량 조건 비교, B 수정 여부·수정량, OLS `PO ~ Cond + 최종 프롬프트 길이` | 시간·길이 교란 점검 |
| 6c | 조건 × 세계관 인원, 세계관별 PO, OLS `PO ~ Cond + World` | 자극(세계관) 점검 |
| 7–8 | 과정 로그 기술통계, 사전 특성 균형 점검 | Appendix A5 |

## 5. 설계상 주의할 점 (발표·보고서에 언급 권장)

1. **검정력**: 조건당 6명이면 80% 검정력(α=.05, 단측)에 **d ≈ 1.54**가 필요 (양측 ≈ 1.80). d = 0.8을 검출하려면 조건당 약 21명. → 제안서대로 효과크기와 CI 중심으로 보고하고, exact permutation test를 함께 제시 (12명이면 924개 배정 전부 열거 가능).
2. **B의 최종 이미지는 마지막 결과로 고정**: 여러 결과 중 '고르는' 관여가 섞이지 않게 함. 단, B 참가자는 2차 결과가 1차보다 나빠도 되돌릴 수 없음 → 안내 화면에 명시, 자유응답에서 불만이 나오는지 확인.
3. **시간·길이 통제의 한계**: 1차 작성 시간과 길이 범위는 맞췄지만, 범위 안에서의 길이와 입력량은 사람마다 다름 → 분석 6b에서 균형을 보고하고 최종 프롬프트 길이를 공변량으로 투입. B의 수정은 선택이라 B 전체 소요 시간은 A보다 길어질 수 있음(조작에 포함되는 차이). 1차 3분이 적절한지 파일럿에서 확인.
6. **스케치 입력의 영향**: 스케치가 서툴면 AI 결과가 스케치 형태에 끌려가 오히려 품질이 떨어질 수 있음. 두 조건에 똑같이 적용되므로 비교에는 문제없지만, 파일럿에서 결과를 보고 `SKETCH_INSTRUCTION` 문구(스케치를 얼마나 강하게 따를지)를 조정.
4. **생성 지연/실패**: 실패한 생성은 자동으로 다시 시도하며 횟수에 포함하지 않고 로그에 남음. 본 실험은 생성 속도가 일정한 유료 API(OpenAI) 권장.
5. **번역 문항**: PO·CC·AU는 영어 원문을 번역/개작함 (앱에 영문 병기). 보고서에 번역 절차와 우리 데이터의 α를 기재.
