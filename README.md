## 1. 실험 설계 요약

| 항목 | 내용 |
|---|---|
| 설계 | 참가자 간 설계(between-subjects), 2조건 |
| IV | AI 이미지 생성에서의 사용자 관여 형태 — **A** 단일 생성 / **B** 반복 프롬프트(1차 결과를 보며 수정 → 바꿨으면 재생성) |
| 유일한 차이 | 1차 결과를 본 뒤 **프롬프트를 수정해 다시 생성할 기회**가 있는지 (작성 시간 총량 5분·길이 범위·스케치 입력은 동일) |

| 세계관(자극) | 2개 — 「별빛 마법학교」 / 「2087 네온시티」. 조건 × 세계관 균형 배정 (각 칸 4명) |
| 1차 DV | 심리적 소유감 PO (Chung et al., 2024 · 5문항 · 7점) |
| 탐색 | 의도 일치도 IA (자체 개발 · 3문항 · 컨셉 시트/스케치 옆에서 평정) |
| 2차 DV | 지각된 저자성 AU (2문항) + 공개 시 저자 표기 (Draxler et al., 2024) |
| 조작 점검 | 지각된 창작 통제감 CC (Gong & Chen, 2026 · 3문항) |
| 공변량 | 지각된 품질, 지각된 노력 (0–100, Pennanen et al., 2026) |
| 추가 문항 | 결과 만족도 (1–7), 지각된 AI 기여도 (0 = 전적으로 나 – 100 = 전적으로 AI) — 파일럿 피드백 반영 |
| 가설 | **H1** B > A (PO). RQ2: IA와 PO의 관계 (조건 포함 회귀) |

### 조건별 조작 (교수님 피드백 반영 — 시간·길이 교란 통제)

| | A · Single Generation | B · Iterative Prompting |
|---|---|---|
| 프롬프트 작성 | **정확히 5분** 1회, 60–400자 → **손 스케치 + 프롬프트**로 생성 | 1차 **정확히 3분**, 60–400자 → 스케치 + 프롬프트로 생성 |
| 1차 결과 이후 | 1차 이미지가 최종 | 1차 결과를 보며 **정확히 2분 수정** (일찍 끝낼 수 없음) → 프롬프트를 바꿨으면 **스케치 + 수정 프롬프트**로 1회 재생성, 그대로면 1차가 최종 |
| 작성 시간 총량 | 5분 | 5분 (3 + 2) |
| 최종 이미지 | 1차 | 수정했으면 2차, 아니면 1차 |
| 생성 횟수 | 1 | 1–2 |

**스케치 반영**: 손 스케치를 이미지 입력으로 함께 보내고(OpenAI `images/edits`), 프롬프트 앞에 "스케치를 자세·실루엣·비율의 주 참고로 삼으라"는 고정 지시문(`SKETCH_INSTRUCTION`)을 붙임. 두 조건, 모든 생성에 동일.

**왜 이렇게 바꿨나 (피드백 요지)**: 처음 설계(A 1회 / B 최대 3회, 6분 내 자유)는 A가 한 줄만 쓰고 일찍 끝내거나 반대로 한 번에 모든 정보를 몰아넣을 수 있어서, 결과 차이가 '횟수' 때문인지 '작성 시간·프롬프트 길이' 때문인지 구분할 수 없었음.

**통제 방법**
- **작성 시간 총량 동일 (세션 단위 시간 고정)**: 이전 안(1차 3분 동일 + B만 수정 3분 추가)은 B가 최대 6분을 쓰게 되어 시간 교란이 남았음. 선행연구도 회차가 아니라 과제 전체 시간을 맞추는 방식을 씀 — LACE(CHI 2025 workshop)는 생성 방식마다 세션 15분 고정, Joshi et al.(2025)은 조건 간 대기 시간을 약 60초로 맞추며 "차이가 결과를 교란할 수 있어서"라고 명시. 그래서 A 5분 1회, B 1차 3분 + 수정 2분 **고정**(수정하지 않아도 2분은 보냄)으로 총량을 완전히 같게 함. 시간 배분은 파일럿 의견("첫 프롬프트 3분은 적당", "수정 3분은 넉넉")을 따름. 글자 수 범위 60–400자 동일.
- **노력·길이는 측정해 통제**: 프롬프트가 길수록 소유감이 높아진다는 결과(Joshi et al., 2025)가 있고, Pennanen et al.(2026)은 노력·품질을 공변량으로 넣고도 차이가 남는지 확인함 → 같은 방식으로 품질·노력 슬라이더와 최종 프롬프트 길이를 공변량으로 투입(분석 6, 6b).
- **사후 점검**: 생성에 실제로 쓰인 작성 시간 합(`write_seconds_total`), 최종·1차 글자 수, 입력량을 조건 간 비교(분석 6b), 최종 프롬프트 길이를 공변량으로 투입.
- **작성 안내**: 두 조건 모두 "최종 이미지에서 표현되기를 원하는 외형, 표정, 의상, 분위기, 핵심 특징을 중심으로, 가능한 한 충실하게" 쓰도록 안내 (파일럿에서 컨셉 시트를 그대로 옮기거나 성격·배경 위주로 쓰는 경향이 있었음). 글자 수 하한(60자)만으로는 불성실 응답을 막기 어려워 안내로 보완.
- **남는 차이 (= 조작)**: B는 1차 결과를 보고 고칠 기회가 있음. 수정은 선택이라 B 안에서 수정한 사람/안 한 사람이 나뉨 → 수정 여부(`b_revised`)와 수정량을 기록해 기술적으로 보고 (자기선택이라 B 내부 비교는 인과 해석 불가). 주 분석은 배정된 조건 기준(A vs B).

### 두 조건 간 동일하게 통제되는 것
- 같은 과제 지시문, 같은 세계관 세트 (각 조건 안에서 두 세계관이 4명씩)
- 같은 창작 경험 구성 (각 조건 안에서 경험 있음 4명 / 없음 4명)

### 창작 경험 층(E/N)으로 나눠 배정한 이유
모집 시 그림·창작 경험이 다양하도록 경험 있음/없음을 반반 모집함. 이것은 조건이 아니라 **층(stratum)**임 (조건 A/B는 여전히 생성 방식). 16명을 한꺼번에 무작위 배정하면 우연히 한 조건에 경험자가 몰릴 수 있고, 경험은 소유감·의도 일치도에 영향을 줄 수 있으므로 층마다 따로 블록 배정해 두 조건의 경험 구성을 맞춤. 분석 6d에서 층별 PO와 `PO ~ Cond + Stratum`을 보고.

### 세계관을 2개로 무작위 배정한 이유
처음 세계관(「등불의 군도」)이 낯설어 이해하기 어렵다는 의견이 있어, 익숙한 장르 두 개로 바꾸고 각각 "이런 인물들이 살고 있어요" 예시를 붙였음. 세계관을 주는 방식은 세 가지를 검토함.

| 방법 | 판단 |
|---|---|
| 참가자가 2개 중 **선택** | ✗ 선택 행위 자체가 자율성·소유감을 높여 종속변수(PO)를 직접 건드림. 자기선택 편향 |
| 한 명당 **2개 모두 진행** | ✗ 소요 시간이 약 2배(45분 이상), 피로와 1회차 학습 효과가 2회차에 섞임 |
| **2개 중 하나를 무작위·균형 배정** | ✓ 결과가 특정 세계관 하나에 국한되지 않음을 보일 수 있음(자극 일반화). 조건마다 세계관 구성이 같아 교란 없음. 분석에서 세계관을 공변량으로 통제(6c) |
- 같은 생성 모델, 같은 숨은 스타일 접미사(`STYLE_SUFFIX`), 같은 출력 크기(768×1024, 3:4)
- AI 사용 **전에** 컨셉 시트 + 손 스케치 작성 (의도를 사전에 고정)
- 같은 사후 설문, 같은 순서

| 6 | AI 생성 안내 | 조건별 규칙 안내 | 0.5분 |

**설문 순서 근거**: 1차 DV(PO)를 가장 먼저 측정해 다른 문항(특히 IA 비교 화면)이 소유감 응답을 오염시키지 않도록 함. IA는 PO 다음에 컨셉 자료를 보여주며 측정.

### 실행
`index.html`을 Chrome에서 더블클릭하여 열기. 서버 불필요. 데이터는 **그 브라우저의 IndexedDB**에 저장되므로 **모든 세션을 같은 노트북·같은 브라우저 프로필**에서 진행할 것.

### 연구자 화면
- **창작 경험 → 참가자 ID**: 모집 때 확인한 경험 유무(E/N)를 먼저 고르면, 그 층 배정표의 다음 ID(E01…/N01…)와 조건·세계관이 자동으로 채워짐.
- **이미지 생성 모델** (기본값: OpenAI — 키가 없으면 세션 시작이 막힘)
  - `Pollinations (FLUX)` — 무료, 키 불필요. **IP당 45초에 1장** 제한(작성 단계가 2분 이상이라 실험 흐름에는 거의 영향 없음). 영어 프롬프트 권장 안내가 자동으로 붙음. → **테스트·파일럿용**
  - `OpenAI GPT Image` — 유료 API 키 필요(그 브라우저 localStorage에만 저장). 모델(gpt-image-1.5 / 1 / 1-mini)과 화질(low/medium/high) 선택. 한국어 프롬프트 이해 우수. → **본 실험 권장: gpt-image-1.5 · medium**. OpenAI 대시보드에서 사용 한도(예: $10)를 걸어 둘 것. 키는 연구자 노트북에만 입력하고 팀원에게 공유하지 말 것.
  - `Mock` — 가짜 이미지. 인터넷 없이 흐름 리허설용.

## 5. 설계상 주의할 점 (발표·보고서에 언급 권장)

1. **검정력**: 조건당 8명이면 80% 검정력(α=.05, 단측)에 **d ≈ 1.31**이 필요 (양측 ≈ 1.51). d = 0.8을 검출하려면 조건당 약 21명. → 제안서대로 효과크기와 CI 중심으로 보고하고, exact permutation test를 함께 제시 (16명이면 12,870개 배정 전부 열거 가능).
2. **B의 최종 이미지는 마지막 결과로 고정**: 여러 결과 중 '고르는' 관여가 섞이지 않게 함. 단, B 참가자는 2차 결과가 1차보다 나빠도 되돌릴 수 없음 → 안내 화면에 명시, 자유응답에서 불만이 나오는지 확인.
3. **시간·길이 통제의 한계**: 작성 시간 총량(5분)과 길이 범위는 맞췄지만, 범위 안에서의 길이와 입력량은 사람마다 다름 → 분석 6b에서 균형을 보고하고 최종 프롬프트 길이를 공변량으로 투입. B의 1차 프롬프트는 A보다 짧은 시간(3분)에 쓰므로 1차 이미지가 덜 정교할 수 있음 — "짧게 쓰고 보고 고치는 방식 vs 한 번에 쓰는 방식"이라는 조작의 일부로 해석. 이미지 생성에서 단일 vs 반복의 시간 통제를 직접 다룬 선례는 찾지 못해, 세션 단위 시간 고정 관행(LACE, Joshi et al.)을 따랐음을 보고서에 명시.
6. **스케치 입력의 영향**: 스케치가 서툴면 AI 결과가 스케치 형태에 끌려가 오히려 품질이 떨어질 수 있음. 두 조건에 똑같이 적용되므로 비교에는 문제없지만, 파일럿에서 결과를 보고 `SKETCH_INSTRUCTION` 문구(스케치를 얼마나 강하게 따를지)를 조정.
4. **생성 지연/실패**: 실패한 생성은 자동으로 다시 시도하며 횟수에 포함하지 않고 로그에 남음. 본 실험은 생성 속도가 일정한 유료 API(OpenAI) 권장.
5. **번역 문항**: PO·CC·AU는 영어 원문을 번역/개작함 (앱에 영문 병기). 보고서에 번역 절차와 우리 데이터의 α를 기재.
