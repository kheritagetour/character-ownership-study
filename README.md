## 1. 실험 설계 요약

| 항목 | 내용 |
|---|---|
| 설계 | 참가자 간 설계(between-subjects), 2조건 |
| IV | AI 이미지 생성에서의 사용자 관여 형태 — **A** 단일 생성 / **B** 반복 수정(1차 결과를 보며 수정 요청 → 적었으면 재생성) |

| 세계관(자극) | 2개 — 「별빛 마법학교」 / 「2087 네온시티」. 조건 × 세계관 균형 배정 (각 칸 4명) |

| 탐색 | 의도 일치도 IA (자체 개발 · 3문항 · 컨셉 시트/스케치 옆에서 평정) |

| 조작 점검 | 지각된 창작 통제감 CC (Gong & Chen, 2026 · 3문항) |
| 공변량 | 지각된 품질, 지각된 노력 (0–100, Pennanen et al., 2026) |
| 추가 문항 | 결과 만족도 (1–7), 지각된 AI 기여도 (0 = 전적으로 나 – 100 = 전적으로 AI) — 파일럿 피드백 반영 |
| 가설 | **H1** B > A (PO). RQ2: IA와 PO의 관계 (조건 포함 회귀) |

### 조건별 조작 (2차 파일럿 피드백 반영 — 프롬프트 직접 작성 제거)

| | A · Single Generation | B · Iterative Revision |
|---|---|---|
| 1차 생성 | 컨셉 시트를 **고정 템플릿으로 자동 변환한 프롬프트 + 손 스케치**로 생성 (참가자는 프롬프트를 쓰지 않음) | A와 동일 |
| 1차 결과 이후 | 1차 이미지가 최종. **2분 동안 결과 살펴보기** (고정) | 1차 결과를 보며 **2분 동안 수정 요청 작성** (고정, 일찍 끝낼 수 없음) → 적었으면 **1차 이미지 + 수정 요청**으로 1회 재생성, 비우면 1차가 최종 |
| 1차 결과를 보는 시간 | 2분 | 2분 |
| 최종 이미지 | 1차 | 수정 요청을 적었으면 2차, 아니면 1차 |
| 생성 횟수 | 1 | 1–2 |

**자동 프롬프트 (`buildPrompt`)**: 컨셉 시트 칸을 항목별로 나열하고 맨 앞에 고정 문구(`AUTO_PROMPT_INTRO`: "가능한 한 충실하게 반영해, 외형·표정·의상·분위기·핵심 특징이 잘 드러나게")를 붙임. 성격은 "표정·자세·분위기로 표현"하도록 넣음. LLM으로 다시 쓰지 않고 템플릿을 쓰는 이유: 같은 컨셉 시트면 항상 같은 프롬프트가 나와 재현 가능하고, LLM이 내용을 더하거나 빼는 변수가 생기지 않음. 참가자는 생성 화면의 "AI에게 전달된 캐릭터 설명 보기"에서 확인 가능 (두 조건 동일).

**스케치 반영**: 1차 생성에는 손 스케치를 이미지 입력으로 함께 보내고(OpenAI `images/edits`), 프롬프트 앞에 "스케치를 자세·실루엣·비율의 주 참고로 삼으라"는 고정 지시문(`SKETCH_INSTRUCTION`)을 붙임. B의 2차 생성은 **1차 이미지**를 입력으로 보내고 "같은 캐릭터를 유지하고 요청한 부분만 바꾸라"는 지시문(`REVISION_INSTRUCTION`) + 수정 요청 + 원래 설정을 보냄.

**설계 변경 경과**
1. 처음 안(A 1회 / B 최대 3회, 6분 내 자유): 결과 차이가 '횟수' 때문인지 '작성 시간·프롬프트 길이' 때문인지 구분 불가.
2. 1차 파일럿 후(A 5분 / B 3분 + 수정 2분, 프롬프트 직접 작성): 작성 시간 총량은 맞췄지만, 2차 파일럿에서 "컨셉 시트를 자세히 쓰고 나서 프롬프트를 또 쓰는 게 중복이고 번거롭다"는 의견이 나옴. 또 프롬프트를 쓰는 능력(프롬프트 리터러시) 차이가 결과 이미지 품질에 섞임.
3. 현재 안: 1차 생성 입력을 **컨셉 시트 + 스케치로 통일**하고, 조건 차이를 "결과를 보고 수정 요청을 할 수 있는가" 하나로 좁힘.

**통제 방법**
- **1차 생성 입력 동일**: 두 조건 모두 같은 템플릿·같은 지시문으로 1차 이미지를 만듦. 참가자 입력량은 컨셉 시트 분량(`concept_chars`)과 작성 시간(`concept_seconds`)으로 조건 간 비교(분석 6b).
- **1차 결과를 보는 시간 동일 (세션 단위 시간 고정)**: B가 수정 요청을 쓰는 2분 동안 자기 캐릭터를 보는 만큼, A도 같은 2분 동안 결과를 봄(`A_VIEW_SEC = REVISION_SEC`). 선행연구도 회차가 아니라 과제 시간을 맞추는 방식을 씀 — LACE(CHI 2025 workshop)는 생성 방식마다 세션 15분 고정, Joshi et al.(2025)은 조건 간 대기 시간을 약 60초로 맞추며 "차이가 결과를 교란할 수 있어서"라고 명시. `image1_view_seconds`가 조건 간 같은지 확인(분석 6b).
- **노력·품질은 측정해 통제**: Pennanen et al.(2026)처럼 품질·노력 슬라이더를 공변량으로 넣고도 차이가 남는지 확인(분석 6), 컨셉 시트 분량도 공변량으로 투입(6b).
- **남는 차이 (= 조작)**: B는 1차 결과를 보고 고칠 기회가 있음. 수정은 선택이라 B 안에서 수정한 사람/안 한 사람이 나뉨 → 수정 여부(`b_revised`)와 수정 요청 분량을 기록해 기술적으로 보고 (자기선택이라 B 내부 비교는 인과 해석 불가). 주 분석은 배정된 조건 기준(A vs B).

### 두 조건 간 동일하게 통제되는 것
- 같은 과제 지시문, 같은 세계관 세트 (각 조건 안에서 두 세계관이 4명씩)
- 같은 창작 경험 구성 (각 조건 안에서 경험 있음 4명 / 없음 4명)

### 창작 경험 층(E/N)으로 나눠 배정한 이유
모집 시 그림·창작 경험이 다양하도록 경험 있음/없음을 반반 모집함. 층은 **사전 설문 응답으로 자동 결정**: 그림 경험 또는 캐릭터·스토리 창작 경험이 "취미로 해 봄" 이상이면 E, 둘 다 "거의 없음"이면 N (`stratumFromPre`). 이것은 조건이 아니라 **층(stratum)**임 (조건 A/B는 여전히 생성 방식). 16명을 한꺼번에 무작위 배정하면 우연히 한 조건에 경험자가 몰릴 수 있고, 경험은 소유감·의도 일치도에 영향을 줄 수 있으므로 층마다 따로 블록 배정해 두 조건의 경험 구성을 맞춤. 분석 6d에서 층별 PO와 `PO ~ Cond + Stratum`을 보고.

### 세계관을 2개로 무작위 배정한 이유
처음 세계관(「등불의 군도」)이 낯설어 이해하기 어렵다는 의견이 있어, 익숙한 장르 두 개로 바꾸고 각각 "이런 인물들이 살고 있어요" 예시를 붙였음. 세계관을 주는 방식은 세 가지를 검토함.

| 방법 | 판단 |
|---|---|
| 참가자가 2개 중 **선택** | ✗ 선택 행위 자체가 자율성·소유감을 높여 종속변수(PO)를 직접 건드림. 자기선택 편향 |
| 한 명당 **2개 모두 진행** | ✗ 소요 시간이 약 2배(45분 이상), 피로와 1회차 학습 효과가 2회차에 섞임 |
| **2개 중 하나를 무작위·균형 배정** | ✓ 결과가 특정 세계관 하나에 국한되지 않음을 보일 수 있음(자극 일반화). 조건마다 세계관 구성이 같아 교란 없음. 분석에서 세계관을 공변량으로 통제(6c) |
- 같은 생성 모델, 같은 숨은 스타일 접미사(`STYLE_SUFFIX`), 같은 출력 크기(768×1024, 3:4)
- AI 사용 **전에** 컨셉 시트 + 손 스케치 작성 (의도를 사전에 고정)
- 같은 사후 설문, 같은 순서

## 2. 절차 (참가자 1인, 약 20분 · 현장 30분 · 준비물: 종이, 펜)

| # | 단계 | 내용 | 예상 시간 |
|---|---|---|---|
| 0 | 연구자 준비 | 앱에서 창작 경험 "자동"(기본값) 그대로 → 세션 시작 | — |
| 1 | 동의 | 연구 안내 + 동의 체크 | 1분 |
| 2 | 사전 설문 | 텍스트/이미지 AI 사용 빈도, 사용 도구, AI 자기효능감, 그림 경험(3단계: 거의 없음/취미/전공·업무), 캐릭터·스토리 창작 경험(3단계), 그림 실력, 나이(만 나이)/성별 → **응답으로 층(E/N) 결정, 그 층 배정표의 다음 칸(조건·세계관) 자동 배정, 참가자 번호는 P01부터 순서대로** | 2분 |
| 3 | 과제 상황 | "여러분은 이 세계를 배경으로 한 인터랙티브 스토리(게임)를 만드는 작가입니다. 이야기에 새로 등장할 인물 한 명을 만들어 주세요. (내 아바타가 아니라 이야기 속 인물)" + 배정된 세계관 소개(인물 구상 참고용이라는 설명) + 진행 순서 | 1분 |
| 4 | 컨셉 시트 | **기본**: 이름 · 역할/직업 · 나이·성별 / **외형**: 키·체형 · 얼굴형 · 눈 · 머리카락 · 피부색 · 옷 · 소지품(없으면 '없음') · 핵심 시각 특징 / **성격**: 성격 키워드(원하는 만큼, 1개 이상) · 성격 설명. 모든 칸 필수(참가자마다 프롬프트에 들어가는 정보 항목을 같게). "AI가 이 내용과 스케치로 이미지를 만드니 최대한 자세히" 안내 | 6분 |
| 5 | 손 스케치 | 앱 내 캔버스(펜/태블릿) 또는 **종이에 펜으로 그려 사진 업로드** | 3분 |
| 6 | 생성 안내 | 조건별 규칙 안내 | 0.5분 |
| 7 | AI 생성 | 공통: 컨셉 시트 + 스케치로 자동 생성(약 1분) / A: 결과 2분 살펴보기 / B: 결과 보며 2분 수정 요청 → (적었으면) 재생성 | A 약 3분 / B 약 3–4분 |
| 8 | 사후 설문 1 | PO 5문항 (최종 이미지 보며) | 1분 |
| 9 | 사후 설문 2 | IA 3문항 (컨셉 시트 · 스케치 · 최종 이미지 3열 비교) | 1분 |
| 10 | 사후 설문 3 | AU 2문항, 공개 시 저자 표기, CC 3문항 | 1.5분 |
| 11 | 사후 설문 4 | 결과 만족도(1–7), AI 기여도·품질·노력 슬라이더, 자유응답 2개(필수, '없음' 가능). 만족도·품질은 '게임 속 공식 캐릭터 일러스트로 쓰인다'는 기준을 제시하고 평정 | 2분 |

> **목표: 30분 이내.** 예상 A·B 모두 약 20분. 넘칠 위험은 컨셉 시트(권장 6분)와 스케치(권장 3분) → 두 화면에 경과/권장 시간을 표시하고 넘기면 마무리 안내(강제 종료는 안 함). 분석 보고서 7절에 총 소요 시간과 30분 초과 인원이 나옴. 모집 공고에는 "약 20분(최대 30분)"으로 표기.

**설문 순서 근거**: 1차 DV(PO)를 가장 먼저 측정해 다른 문항(특히 IA 비교 화면)이 소유감 응답을 오염시키지 않도록 함. IA는 PO 다음에 컨셉 자료를 보여주며 측정.

### 연구자 진행 스크립트 (구두)
1. "오늘은 이야기 작가가 되어 등장인물 한 명을 만들고, AI 도구로 그 모습을 완성하는 과제를 하게 됩니다. 화면 안내를 따라가시면 되고, 그림 실력은 평가하지 않습니다."
2. 세션 시작 후 참가자에게 노트북을 넘기고, 생성 단계 중에는 **도움을 주지 않음** (수정 요청 조언 금지).
3. 질문이 오면: "화면에 적힌 안내대로 진행하시면 됩니다."
4. 완료 화면이 뜨면 Ctrl+Shift+A로 연구자 화면 복귀 → 다음 참가자.
5. 사후 디브리핑: 두 조건이 있었고 무작위 배정되었다는 점 설명.

## 5. 설계상 주의할 점 (발표·보고서에 언급 권장)

1. **검정력**: 조건당 8명이면 80% 검정력(α=.05, 단측)에 **d ≈ 1.31**이 필요 (양측 ≈ 1.51). d = 0.8을 검출하려면 조건당 약 21명. → 제안서대로 효과크기와 CI 중심으로 보고하고, exact permutation test를 함께 제시 (16명이면 12,870개 배정 전부 열거 가능).
2. **B의 최종 이미지는 마지막 결과로 고정**: 여러 결과 중 '고르는' 관여가 섞이지 않게 함. 단, B 참가자는 2차 결과가 1차보다 나빠도 되돌릴 수 없음 → 안내 화면에 명시, 자유응답에서 불만이 나오는지 확인.
3. **입력량·시간 통제의 한계**: 1차 생성 입력(컨셉 시트 + 스케치)과 1차 결과를 보는 시간은 맞췄지만, 컨셉 시트를 얼마나 자세히 쓰는지는 사람마다 다름 → 분석 6b에서 균형을 보고하고 컨셉 시트 분량을 공변량으로 투입. A의 2분 "살펴보기"는 B의 노출 시간에 맞추기 위한 것으로, A 참가자가 지루해하거나 이상하게 느끼는지 파일럿에서 확인. 이미지 생성에서 단일 vs 반복의 시간 통제를 직접 다룬 선례는 찾지 못해, 세션 단위 시간 고정 관행(LACE, Joshi et al.)을 따랐음을 보고서에 명시.
4. **프롬프트를 직접 쓰지 않는 설계**: 참가자의 언어적 기여가 프롬프트가 아니라 컨셉 시트에서 이뤄짐. 프롬프트 작성 능력 차이를 없애는 대신, "AI에 직접 지시한 경험"은 B의 수정 요청에만 있음 → 이것이 조작의 핵심이라는 점을 보고서에 명시.
5. **스케치 입력의 영향**: 스케치가 서툴면 AI 결과가 스케치 형태에 끌려가 오히려 품질이 떨어질 수 있음. 두 조건에 똑같이 적용되므로 비교에는 문제없지만, 파일럿에서 결과를 보고 `SKETCH_INSTRUCTION` 문구(스케치를 얼마나 강하게 따를지)를 조정.
6. **생성 지연/실패**: 실패한 생성은 자동으로 다시 시도하며 횟수에 포함하지 않고 로그에 남음. 본 실험은 생성 속도가 일정한 유료 API(OpenAI) 권장.
7. **번역 문항**: PO·CC·AU는 영어 원문을 번역/개작함 (앱에 영문 병기). 보고서에 번역 절차와 우리 데이터의 α를 기재.
